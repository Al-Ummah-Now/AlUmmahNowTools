# Releasing Al Ummah Now Tools

`.github/workflows/release.yml` builds, checks and publishes every release (wiki TOOLS-ADMIN, TA-15).

## Cut a release

1. Make sure `master`'s latest commit is green (`.NET Tests and Coverage`).
2. Check `packaging/SERVER-REQUIREMENTS.md`: every page in this release has its row, with the first videos
   release that serves it. A Tools PR that calls a new server route adds its row in the same PR.
3. Tag `master` with the US Eastern date (America/New_York, as the videos releases):
   ```sh
   git fetch origin
   tag=v$(TZ=America/New_York date +%Y.%m.%d)          # first release that day
   git tag -l "$tag*"                                   # taken? use $tag.2, $tag.3, ...
   git tag "$tag" origin/master && git push origin "$tag"
   ```
   Never move or reuse a tag. To retry a failed release, re-run that tag's workflow run.
4. Follow the `Release` run. It publishes the GitHub release at the end; share its link with staff.

## What the run does

| Job | Does |
|---|---|
| Version and tests | Refuses a tag that is not on `master` or not `vYYYY.MM.DD[.N]`; runs ToolsCore and importer tests; lists the NuGet packages' licences |
| windows | `win-x64` self-contained publish; portable `.zip`; per-machine `.msi` (WiX 5, `packaging/windows/tools.wxs`); installs the MSI, launches the installed app, uninstalls |
| macos | `osx-arm64` and `osx-x64` `.app` bundles (Uno `PackageFormat=app`) in `.dmg`s; launches the arm64 app |
| linux | `linux-x64` self-contained `.tar.gz` and `.deb` (`scripts/build-deb.sh`); installs the `.deb`, launches it under Xvfb, removes it |
| release | `SHA256SUMS.txt`, `AlUmmahNow-Tools-<version>-licenses.zip`, notes (`scripts/release-notes.py`: install table, signing warnings, server requirements, PRs merged since the previous tag), then the GitHub release |

The launch check starts the installed app in demo mode (`TOOLS_DEMO=1`, no network, no sign-in) with
`TOOLS_SCREENSHOT`, which renders the window to a PNG and exits; no PNG within 120 s fails the run. The PNGs are
the `smoke-*` artifacts.

A pull request that changes `release.yml`, `packaging/**` or the release scripts runs the same jobs as a dry
run (version `vYYYY.MM.DD.0`, no release); so does **Run workflow** on the Actions page.

## Versions

Tag `vYYYY.MM.DD[.N]` (N is 1 when absent) becomes:

| Where | Value | Example for `v2026.11.22.2` |
|---|---|---|
| File names, About, `InformationalVersion`, `.deb` | tag without `v` | `2026.11.22.2` |
| Assembly and file version | `YYYY.M.D.N` | `2026.11.22.2` |
| MSI `ProductVersion` (major ≤ 255, only 3 fields compare) | `YY.M.(D×100+N)` | `26.11.2202` |
| Uno `ApplicationDisplayVersion` / `ApplicationVersion` (macOS `CFBundleShortVersionString` / `CFBundleVersion`) | `YYYY.M.D` / `N` | `2026.11.22` / `2` |

## Signing

The run never fails for a missing signing value; it ships unsigned files named `*-unsigned.*`, says so in the
notes, and logs a `::notice::` naming what is missing. Set these repository (or organization) secrets:

| Platform | Secrets | Same names as |
|---|---|---|
| Windows Authenticode (exe and MSI) | `WINDOWS_CERT_PFX_BASE64`, `WINDOWS_CERT_PASSWORD` | AlUmmahNowDesktop `release.yml` |
| macOS Developer ID signing | `DEVELOPER_ID_P12` (base64 `.p12` of the *Developer ID Application* certificate), `DEVELOPER_ID_P12_PASSWORD`, `APPLE_TEAM_ID` | AlUmmahNowApple `release.yml` |
| macOS notarization | `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8` (App Store Connect API key, text of the `.p8`) | AlUmmahNowApple |

Signed macOS apps use the hardened runtime with `packaging/macos/entitlements.plist` (JIT and loading aun-core
and SkiaSharp). The `.dmg` is notarized and stapled.

## Third-party licences

`packaging/licenses/` goes into every package (a `licenses` folder next to the app; `/usr/share/doc/alummahnow-tools`
too on Linux) and into the release's licences zip:

- `THIRD-PARTY-NOTICES.md`: what is bundled and what is not (FFmpeg and OpenH264 are not bundled yet; the rules
  for when they are, TA-19), whisper.cpp, the Whisper models (downloaded on first use);
- `whisper.cpp-MIT.txt`, `openai-whisper-models-MIT.txt`;
- `aun-core-rust-crates.txt`: regenerate with `scripts/core-crate-licenses.py` whenever `scripts/fetch-core.sh`
  pins a new Core (instructions in the script);
- `NUGET-PACKAGES.txt`: generated by the run (`scripts/nuget-notices.py`), not committed.

## Updates

The app asks `GET /api/v1/app-config` for a newer release and installs only what our own key signed (wiki
AUN-APP-UPDATES). Operating-system code signing is separate and optional.

- **Windows Setup and the macOS `.dmg`** are Velopack builds (`scripts/vpk-pack.sh`) and update themselves. The MSI, the
  portable zip and the Linux packages show the notice, and **Download** opens the releases page.
- **`packaging/release-notes/en.txt` and `ar.txt`**: plain text, at most 1,500 characters each, shown under *What's new*.
  Change both before each release; a tag whose notes are the last release's is refused.
- **`app-release.json`** lists every file with its SHA-256 (`scripts/release-files.mjs`, `scripts/app-release.mjs`, a copy
  of AlUmmahNow `scripts/app-release/app-release.mjs`). The `sign` job signs it with `UPDATE_SIGNING_KEY` from the
  environment `update-signing`, and refuses a commit that isn't on `master`. A failed signature means no release.
- **Keys**: the root public key is in `AlUmmahNow.ToolsCore/Updates/CoreUpdateChecker.cs`; the root-signed key list is
  `AlUmmahNow.ToolsCore/Updates/keys/`, byte for byte the one on the `update-keys` release. Rotation and revocation:
  wiki §3.5.
- **Update test** (`.github/workflows/update-test.yml`): builds two versions with a test key, installs the first, and
  checks that it becomes the second on Windows and macOS, and that a changed package is refused. Test builds
  (`-p:UpdateTest=true`) are the only ones that take their key and server from the environment; `release.yml` never
  sets it, and a check refuses it there.
